# Adding a new species

**Redesign routing:** use [the current creature contract](../design/creature-model-current.md), [derived-act rules](../design/creature-derived-acts.md), and the updated `migrate-species` skill for v5 authoring. Stage redesigned templates in `docs/species-templates/v5/` and validate with `npm run check:creature-model -- <path>`. After ratification run `npm run sync:species` and `npm run check:species`; this adds a species content revision without changing generator code or its archive. The numbered workflow below describes the existing v4 publishing pipeline, not v5 schema authority. Do not add retired traits or move pools to a v5 template to satisfy that pipeline.

The checklist for a creature that does not yet exist. Every path is relative to the creature worktree root. Each step's output is checked by the next step's tool; nothing is hand-copied between files.

**Required ability coverage:** complete [ABILITY-AUDIT.md](ABILITY-AUDIT.md) during the record-authoring step and save the species review as `<key>.ability-audit.md`. Include the review in validation/presentation and ship it with the authoring artifacts. Apply the same checklist when editing an existing species' defining facts or abilities, updating the prior audit for affected families. Derive all table-granted acts from anatomy, channels and conduits, evaluate each against the source, and explore supported extensions the tables cannot say. Four generated actions are not a species-level cap. A few examples, a tidy pool, or a schema pass alone do not establish coverage. Record concrete exclusions and equivalences; the checklist does not authorize unimplemented schema changes or newly invented species powers.

1. **Teaser and legacy entry.** Nick writes the teaser (the `description`; it is carried verbatim into `lore.description` and never rewritten). Run `node docs/species-templates/tools/new-species.js --key <key> --name <Name> --element <Element> --planet <Planet> --height "<in> in / <cm> cm" --weight "<lbs> lbs / <kg> kg" --description "<teaser>"`. It appends the entry to `packages/content/json/species.json` with the next id and adds a pending row to `docs/species-templates/lore-status.json`. The legacy `statRatings` and `traits` blocks are left empty or at their floor; they are a relative gauge only and retire with the duel derivation layer.
2. **Art.** Put the render at `docs/species-templates/art/<key>.png` (and the SVG under `apps/web/src/svg/species/` for the site). The migration agent reads the art as a source on equal footing with the teaser, so it must exist first.
3. **Record.** Run the `migrate-species` skill for the key. It writes `docs/species-templates/<key>.json`, the walkthrough `<key>.md`, and appends the encyclopedia entry to `docs/encyclopedia/encyclopedia.json`. Sources are the teaser, the art, `packages/content/json/planetRecords.json` and `planetStatus.json`, and the ability catalog; nothing else.
4. **Validate.** `node docs/species-templates/tools/validate-template.js <key>` until it prints `0 FAIL`; every WARN answered in the walkthrough. Run the lore-factcheck skill on the prose. Run `node docs/species-templates/tools/validate-template.js --review <key>` and act on every denial (override file, script fix, or nothing).
5. **Present and ratify.** Present inline in planet batches; explicit sign-off ratifies. On ratification: add the key to `docs/species-templates/RATIFIED.json`, set `appearance`, `fields`, and `traits` to `ratified` in `lore-status.json`, run `node scripts/bundleLore.js` (rebuilds `packages/content/json/speciesRecords.json`, `encyclopedia.json` and the catalog bundle) and `node scripts/checkCatalogCoverage.js` (no thin cells, no species under the name floor).
6. **Ship.** Commit the record, walkthrough, encyclopedia, manifest, status file, validation log and bundles together; open the PR and arm auto-merge. CI fails if the bundle is stale or any ratified record fails the validator.

What stays out of the record: review status (lives in `lore-status.json`), amendments (the walkthrough changelog), game rules (each game derives from the record), and anything not traceable to a source.
