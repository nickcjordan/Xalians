# Adding a new species

The checklist for a creature that does not yet exist, under the v5 creature model (the only model since 2026-10-06, issue #796). Authority: [the current creature contract](../design/creature-model-current.md), [derived-act rules](../design/creature-derived-acts.md), and the `migrate-species` skill. Every path is relative to the repository root. Each step's output is checked by the next step's tool; nothing is hand-copied between files.

**Required ability coverage:** complete [ABILITY-AUDIT.md](ABILITY-AUDIT.md) during the record-authoring step and save the species review as `v5/<key>.ability-audit.md`. Apply the same checklist when editing an existing species' defining facts or abilities, updating the prior audit for affected families. Derive all table-granted acts from anatomy, channels and conduits, evaluate each against the source, and explore supported extensions the tables cannot say. Four generated actions are not a species-level cap. A few examples, a tidy pool, or a schema pass alone do not establish coverage. Record concrete exclusions and equivalences; the checklist does not authorize unimplemented schema changes or newly invented species powers.

1. **Teaser and legacy entry.** Nick writes the teaser (the `description`; it is carried verbatim into `lore.description` and never rewritten). Run `node docs/species-templates/tools/new-species.js --key <key> --name <Name> --element <Element> --planet <Planet> --height "<in> in / <cm> cm" --weight "<lbs> lbs / <kg> kg" --description "<teaser>"`. It appends the entry to `packages/content/json/species.json` with the next id (the site's species ids and the duel prototype still read that legacy file). The legacy `statRatings` and `traits` blocks are left empty or at their floor; they retire with the duel derivation layer.
2. **Art.** Put the render at `docs/species-templates/art/<key>.png` (and the SVG under `apps/web/src/svg/species/` for the site). The migration agent reads the art as a source on equal footing with the teaser, so it must exist first.
3. **Record.** Run the `migrate-species` skill for the key. It writes `docs/species-templates/v5/<key>.json`, the ability audit `docs/species-templates/v5/<key>.ability-audit.md`, and appends the encyclopedia entry to `docs/encyclopedia/encyclopedia.json`. Any new registry key needs a `docs/species-templates/registries.json` row.
4. **Validate.** `npm run check:creature-model -- docs/species-templates/v5/<key>.json` until it compiles, with naming collisions near zero. Run the lore-factcheck skill on the prose.
5. **Present and ratify.** Present inline; explicit sign-off ratifies. On ratification run `node scripts/bundleLore.js` (rebuilds `canonicalSpeciesCatalog.json`, `registries.json` and `encyclopedia.json` in `packages/content/json/`), `node docs/species-templates/tools/validate-all.js`, `node scripts/creatureCoverage.js`, and `npm run simulate:creatures -- --calibrate` (the grade calibration covers the whole roster).
6. **Ship.** Commit the record, audit, encyclopedia entry, bundles and regenerated reports together; open the PR and arm auto-merge. CI fails if the bundle is stale, any species fails `validate-all.js`, or the coverage or simulation reports are stale.

What stays out of the record: amendments (the ability audit's notes), game rules (each game derives from the record), and anything not traceable to a source.
