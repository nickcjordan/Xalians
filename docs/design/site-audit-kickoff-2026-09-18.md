# Site audit remediation: kickoff for the orchestrator

Written for: the Opus orchestrator. Nick starts an Opus session anywhere and hands it one sentence pointing at this file. Nothing else is asked of him during the program; every step below is yours, and you run to completion without asking him for anything.

## Start here, in order

1. Go to the prepared worktree: `cd C:/dev/src/xalians-remediation`. It is a detached checkout of `origin/main` of `nickcjordan/Xalians` with `npm ci` already done. If the folder does not exist, create it: `cd C:/dev/src/Xalians && git fetch origin main && git worktree add C:/dev/src/xalians-remediation origin/main && cd C:/dev/src/xalians-remediation && npm ci`. Either way, run `git fetch origin main && git checkout --detach origin/main` so you are at the tip.
2. Confirm these exist: `docs/design/site-audit-brief-2026-09-18.md` (the design authority), `docs/design/site-audit-2026-09-18.md` (the audit behind it), `scripts/audit/verify.mjs`, `scripts/audit/README.md`, `scripts/audit/run-log.template.md`, and the skill `.claude/skills/site-audit-remediation/SKILL.md`. GitHub issues #423 to #445 carry the per-issue acceptance criteria.
3. If `untracked/site-audit-run.md` is missing, copy `scripts/audit/run-log.template.md` to that path. If `untracked/site-audit/before/report.md` is missing, run `node scripts/audit/verify.mjs --routes audited --out untracked/site-audit/before`. Baseline on main as of 2026-09-18: apps/web 1354 tests, packages/content 54, packages/rules 375, all passing; re-run `npm test -- --run` in each of those three folders and record the result at the top of the run log. If anything fails on main, file an issue and note it; do not fix it inside a wave PR unless it blocks that PR.
4. Read the brief in full, then `CLAUDE.md`, `docs/BACKLOG.md`, and sections 1, 2 and 10 of `docs/DESIGN_SYSTEM.md`. Read each issue when you start it.
5. Run the waves exactly as the brief's section 4 lays them out. For each issue: cut a worktree from `origin/main` (`git worktree add C:/dev/src/xalians-audit-<issue> -b audit/<issue>-<slug> origin/main`; run `npm ci` there), spawn a Sonnet builder with the Agent tool, giving it the issue body, the brief's section for that issue, and the brief's ground rules (not the whole brief); when it reports done, review the diff yourself, run `node scripts/audit/verify.mjs --base http://localhost:3000 --routes <affected routes>` against a dev server in that worktree, then spawn a Sonnet critic with the brief's section 6 checklist and the issue's acceptance criteria. Merge only on an all-pass verdict; otherwise send the failing criteria back to the builder. Open the PR ready, with `Fixes #N`, and arm auto-merge at once. Update the run log at every state change; if your context resets, resume from the earliest unfinished row instead of starting over.
6. After each wave merges, fetch main, wait for the deploy (the bundle hash in the served `index.html` at `https://www.xalians.com` changes), and run `node scripts/audit/verify.mjs --routes <the wave's routes>` against the deployed site. A regression found there is fixed before the next wave starts.
7. Clean up each finished worktree with `npm run wt -- --prune --yes` from the repo root.
8. Lore text goes through `.claude/skills/lore-factcheck/SKILL.md` before commit, every time. Species and planet prose obeys `.claude/skills/lore-voice/SKILL.md`.
9. Anything out of scope becomes a labeled GitHub issue the moment it is found.
10. Never hand a merge or a decision to Nick. The brief already contains every copy, layout and vocabulary decision. Where it says "verify" or "confirm", read the named source, choose the reading the source supports, and record it in the PR body and the run log. If a ratified document flatly contradicts the brief, follow the document, say so in the PR, and continue.
11. When every issue is closed, run `node scripts/audit/verify.mjs --routes audited --out untracked/site-audit/after`, clean up worktrees, and deliver the final report described in the brief's section 8, with the before and after pairs on an Artifact page and real token usage.

## Cost discipline

Builders and critics run on Sonnet. You run on Opus and read every diff, but you do not re-read the whole brief into every subagent: give each builder only its own section, the ground rules, and the issue body. Keep the run log short. Report real token usage in the final report.
