# Ability redesign completion review

## Completed contract

- Separate deliberate actions from automatic passives. Chosen reactions remain actions.
- One signature reference resolves to a guaranteed action or passive; no duplicate definition.
- Random standard actions use authored compatible sets. Required identity and prerequisites remain guaranteed.
- Separate delivery from effects, with bounded operation and trigger vocabulary.
- Categorical range, area shape/extent/anchor, selectivity, preparation, recovery, onset, persistence, duration, and likelihood.
- One primary effect; compound effects share one overall intensity and may narrow recipient compatibility.
- Status catalog: 26 stable keys with display names, condition definitions, descriptive families, applicability guidance, and boundaries.
- Removal catalog: eight named methods; explicit many-to-many matching per application, default all matching, no automatic elemental cures.
- Positive statuses, harm, restoration, protection, restraint, displacement, transfer, and discovery use typed payloads.
- Pure-support species remain valid. No universal damaging-action requirement.
- Current encounter statuses remain outside the permanent creature record.
- Templates and patterns validate before canonical generation; frozen pools compile once. No completed-creature evaluation or retry loop.
- Historical record readers and immutable release archives preserve replay.
- All 32 ratified templates migrated; new spatial/timing choices documented separately from source lore.
- Authoring guidance, five executable worked examples, schema regression tests, record display, and release gates updated.

## Audit corrections

The review caught recipient compatibility bypasses and impossible self-only targets/transfers. Release generation-0.5.0-3 rejects these during definition validation. The catalog completion adds the agreed authoring metadata without new statuses or runtime conditions.

Applicability guidance belongs to reusable design authoring. It does not encode an endless condition language or require human review of each generated creature. Games still resolve encounters using their own typed recipient facts.

## Explicitly outside this redesign

Numerical combat balance, game-specific implementations, turn/event scheduling, and game-specific eligibility behavior are separate work. The user chose to allow creatures with unsupported capabilities explicitly unavailable in a game. That decision is recorded for later implementation; game changes are deferred until this redesign is finished.

No new species powers follow automatically from this schema or catalog. In particular, neither an element nor a descriptive status family automatically grants a status, immunity, or cure.
