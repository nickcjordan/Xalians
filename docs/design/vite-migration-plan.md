# Vite migration plan

Tracking issue: #25 (closed as "reopen when a scoped Vite migration is warranted"). This PR is that migration. Branch `chore/vite-migration` off `master`, worktree `C:\dev\src\xalians-vite`.

## Context

`my-app/` is a Create React App 5 (react-scripts 5.0.1, webpack 5.74) frontend on React 17. Its build only works on modern Node with `NODE_OPTIONS=--openssl-legacy-provider`, because webpack 5.74 hashes with md4 which OpenSSL 3 removed, and both CI workflows set `CI: "false"` because CRA promotes lint warnings to build errors. Issue #25 recorded that a craco override of `output.hashFunction` does not fix it and that the correct fix is a Vite migration. This plan does exactly that and nothing else: same React, same dependencies except the toolchain, same routes, same `build/` output directory, same S3 deploy step.

The 2026-09-01 survey established the ground truth (75 JSX-bearing `.js` files, one `REACT_APP_` env var, four `process.env.NODE_ENV` sites, vendored Club GSAP tarball, the `copy-json` / `copy-js` steps that overwrite `src/json`, `src/constants`, `src/gameplay` from `lambda/src`). A second pass on the worktree found four more things the survey did not list, which are the real risk in this migration and are recorded in the decisions table: CommonJS `module.exports` files inside `src/`, CRA-style `import { ReactComponent }` SVG imports, webpack-style `require()` calls in three components, and the root `package.json` `browser` field.

## Phases

### Phase 0. Baseline (done before any change)

Fresh `yarn install --frozen-lockfile --ignore-engines` in the worktree, `yarn copy-json && yarn copy-js`, then a timed `yarn build` with `NODE_OPTIONS=--openssl-legacy-provider CI=false`, and a timed `yarn start` measured to the first "Compiled" line. Numbers go in the PR description.

### Phase 1. Toolchain swap (orchestrator)

Add `vite`, `@vitejs/plugin-react`, `vite-plugin-svgr`, `vite-plugin-commonjs`, `vitest`, `jsdom` as devDependencies. Remove `react-scripts` and the dead webpack set. Author `my-app/vite.config.js` covering: react plugin, svgr in CRA compatibility mode, commonjs plugin, JSX loader for `.js` in `src/`, `build.outDir = 'build'`, `server.port = 3000` (CRA's port so bookmarks and the Cognito callback config keep working), and the `test` block for Vitest. Rewrite the scripts: `dev` (copy then `vite`), `start` (alias of `dev`), `build` (`vite build`), `preview`, `test` (`vitest`), `build-deploy` and `deploy` unchanged apart from the build they call.

### Phase 2. Mechanical edits (Sonnet subagents, one file set each, run in parallel)

- Subagent A: move `public/index.html` to `my-app/index.html`, add `<script type="module" src="/src/index.js">` immediately after `<div id="root">`, keep every other tag and comment byte for byte.
- Subagent B: `dbApi.js:46` reads `import.meta.env.VITE_USE_CACHE`; `.env.development` sets `VITE_USE_CACHE=false`.
- Subagent C: CI YAML. `ci.yml` drops both `NODE_OPTIONS` and `CI: "false"`, test step becomes `yarn test --run --passWithNoTests`. `deploy-frontend.yml` drops `NODE_OPTIONS` and `CI: "false"` from the build step and nothing else. `deploy-backend.yml` is untouched (it only touches `lambda/`).
- Subagent D: `CLAUDE.md` Commands section and `my-app/README.md` describe the new scripts. `docs/BACKLOG.md` is untouched.

`package.json` is edited only by the orchestrator.

### Phase 3. Gates (orchestrator, every one run by hand)

1. `rm -rf node_modules && yarn install --frozen-lockfile --ignore-engines` after regenerating `yarn.lock`.
2. `yarn test --run`: `duelRules.test.js` and `designTokens.test.js` pass with their real assertion counts; the two untracked `longReturn` tests pass when temporarily copied in.
3. `yarn build` with no `NODE_OPTIONS` in the environment, output in `build/`, `build/index.html` references hashed chunks and `/assets/css/system.css`.
4. `yarn dev` serves on 3000 with zero console errors on `/`, `/duel`, `/styleguide`.
5. Screenshots of `/duel` and `/styleguide` at 1x, compared against a stated expectation before looking. Element theming via `--g-el` checked by reading a computed color off a themed chip, GSAP checked by observing an animated property change between two frames.
6. `curl` of `/assets/css/system.css` from the dev server and presence of `build/assets/css/system.css` in the build.
7. Timings for dev start and build recorded next to the baseline.
