# The Codex: one public URL that carries the whole of Xalia

Status: contract, 2026-09-04. Requested by Nick: "point an LLM to a single endpoint" so a tool such as NotebookLM can build a podcast from the lore without crawling the site. Builder: a Sonnet agent working from this document. Verification: Fable.

## Context

The site is a Vite single-page app served from S3 behind CloudFront. Every encyclopedia page is rendered by JavaScript, so a URL fetcher that does not execute scripts (NotebookLM's website import, most LLM browsing tools, search crawlers) receives an empty shell. There is no page on xalians.com today from which a machine can read one word of lore.

The lore already has one structured home per kind of data (Nick's ruling, 2026-09-03): entries in `docs/encyclopedia/encyclopedia.json`, the chronicle in `docs/encyclopedia/chronicle.json`, the First Survey in `docs/encyclopedia/tour.json`, species records in `docs/species-templates/<key>.json` listed by `RATIFIED.json`, registry display names in `docs/species-templates/registries.json`, and the world records with their histories in `lambda/src/json/planetRecords.json` (the file `my-app/src/lore/worlds.js` reads). A long-form reading copy already exists as `docs/CANON_COMPENDIUM.md`, generated by `scripts/buildCanonCompendium.js` from the legacy `species.json` and a substring match for glossary terms; it predates the chronicle, the tour, the species templates and the aliases, and it is not published anywhere.

The whole corpus is about sixty thousand words. NotebookLM accepts roughly five hundred thousand words per source, so one document is enough.

## Outputs

All generated by `node scripts/buildCodex.js` (repo root), written into `my-app/public/`, which Vite copies verbatim into `build/`. All gitignored.

| File | Purpose |
|---|---|
| `public/lore/xalia.md` | The Codex. The URL to hand to NotebookLM: `https://xalians.com/lore/xalia.md` |
| `public/lore/xalia.txt` | Byte-identical twin of the Markdown for importers that reject `text/markdown` |
| `public/lore/xalia.html` | The same document as script-free semantic HTML with a small inline stylesheet, for importers that want a page. No external CSS, no JavaScript, no site chrome. |
| `public/lore/xalia.json` | The structured bundle for tools: `{ version, sources, preamble, tour, chronicle, worlds, entries, species, aliases }`, exactly the data the Markdown was built from |
| `public/llms.txt` | Root pointer: a one-paragraph description of Xalia and the four URLs above, in the llms.txt format |

Deterministic: no timestamps. `version` is the concatenation of the source file versions (`encyclopedia.version`, `chronicle.version`, `tour.version`, `RATIFIED.version`, `registries.version`). Running the script twice produces identical bytes.

## Document order (the Markdown)

1. **Title and preamble.** Title "Encyclopedia Xalia: The Codex". The preamble says what the document is (the complete published canon of the world of Xalia, generated from the archive's sources, one file), how it is ordered, that the timeline is deliberately undated (chronicle note), that names in Small Caps in the site appear here as plain titles, and that the archive keeps three questions open without answering them: what the weapon on Phantiri's moon is, what was found at Deepwater Black on Endessa, and what built the Veridium worldship. These are stated as three separate questions in three separate sentences, with no suggestion that they share a cause. Nothing else in the preamble makes a claim about the world. Historian's voice, American English, no dashes of any kind, no numbers written as digits except the counts of worlds, species, entries and eras.
2. **A note for readers that are machines.** One short paragraph: every proper name has an entry in the Encyclopedia section, aliases are listed in the Index of Names, cross-references appear as "See also" lines, and the four formats of this document are listed with their URLs.
3. **Foreword: The First Survey.** The eight tour beats in order: `## Beat title`, a line naming its era and the worlds it touches, then the prose.
4. **The Chronicle.** One `## Era name` per era in `order`, its definition, then a numbered list of that era's events in `order`: `title` in bold, then in parentheses the planets involved, and if `firmness` is not `firm` the word "conjectural" or whatever the firmness value states. Under each event, its anchor quotes as `> "quote" (World, paragraph N)`. Events with `entry` set add "See also: Entry Title".
5. **The Worlds.** One `## World name` per world in `planetRecords.json` order, then: a data line (element, terrain, size, radius, gravity, temperature range), the environmental report as a block quote (reuse the compendium's `reportBlock` shape), `### History of <World>` with every paragraph printed once and prefixed by its era in brackets, `[The End Wars]`, taken from `chronicle.paragraphs` by planet and index (paragraphs with no chronicle row are prefixed `[Untagged]` and counted as a build warning), then `### Native species` as a comma list of species names linking nowhere, then `### Encyclopedia entries about <World>`: the world's own entry definition, and the titles of every entry whose `related` includes the world key.
6. **The Encyclopedia.** One `## Category` section per category in `encyclopedia.categories` order, excluding `xalians` (species are the Bestiary). Entries alphabetical by title. Each entry: `### Title`, an "Also called" line when aliases exist, the definition, and a "See also" line listing related titles (resolved from keys; unresolved keys are a build error, not silently skipped).
7. **The Bestiary.** One `## Species name` per ratified species, ordered by home world in world order then alphabetically. A data line (element, home world, other generator worlds if any, body plan, covering, height and weight ranges, lifespan, diet, corporeality when not corporeal), the encyclopedia definition for that species (from `encyclopedia.json`, category `xalians`, matched by key; a missing entry is a build error), the record's description, the biome niche as a sentence "Niche: ...", the three highest traits by display name in a sentence, the signature ability as `**Name.** description`, and "See also" for the species entry's related titles. Every registry key printed goes through `registries.json` display names; a key with no registry row is a build error.
8. **Index of Names.** Alphabetical: every entry title, every alias, every world, every species, every era, each with its kind and the section it lives in. Aliases point to their entry: "Kozrak, see King Kozrak".

The HTML twin renders the same headings and paragraphs (`h1`, `h2`, `h3`, `p`, `blockquote`, `ol`, `ul`, `strong`), one `<style>` block, a `<title>`, `<meta charset>`, `<meta name="viewport">`, and nothing else. No design-system dependency: this page is a document, not a panel.

## Wiring

- `my-app/package.json`: new script `"codex": "node ../scripts/buildCodex.js"`; `dev` and `build` run it first (`"build": "npm run codex && vite build"`). CI and the deploy workflow call `yarn build`, so nothing changes there.
- `my-app/.gitignore`: add `/public/lore/` and `/public/llms.txt`.
- Retire `scripts/buildCanonCompendium.js` and `docs/CANON_COMPENDIUM.md`. Update every reference (`CLAUDE.md`, `.claude/skills/lore-voice/SKILL.md`, `docs/encyclopedia/ENCYCLOPEDIA-INTERNAL.md`, `docs/design/xalian-encyclopedia-page.md`) to name `node scripts/buildCodex.js` and `my-app/public/lore/xalia.md` as the long-form reading copy, generated, never committed.
- The Encyclopedia's Index section gains one line at its foot, in the design system's voice: a `.g-record`-style note "The whole archive as one document" with three plain links (Markdown, HTML, JSON) to `/lore/xalia.md`, `/lore/xalia.html`, `/lore/xalia.json`, opening in a new tab. No new colors, no glow, one CSS block in `Index.css`.

## Tests

`my-app/src/lore/__tests__/lore.codex.test.js` requires the builder (`scripts/buildCodex.js` exports `build()` returning `{ markdown, html, json, llms, warnings }` without touching the filesystem; the CLI entry writes files only when run directly) and asserts:

- every entry title, world name, species name and era name appears in the Markdown at least once as a heading;
- no species heading, world heading or entry heading appears twice;
- every tour beat title appears once, in tour order;
- the Markdown contains no `undefined`, `[object Object]`, `NaN`, or `null` tokens;
- the preamble and the machine note contain no em-dash, en-dash, or double hyphen, and no digits other than the four counts;
- no raw registry key (a lowercase token containing a hyphen, such as `non-corporeal`) appears in the Bestiary section outside of code spans, using the registries' key list;
- `warnings` is empty (every history paragraph carries an era);
- the HTML contains no `<script`, no `<link`, exactly one `<style`, and the same set of `h2` headings as the Markdown;
- `llms.txt` names all four URLs;
- `build()` is deterministic: two calls return identical strings.

Existing suites must stay green.
