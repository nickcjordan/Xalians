# Creature production pipeline: gap audit

Status: audit, 2026-10-14, revised the same day after a cold challenge by an independent Opus reviewer (findings folded in; section 6). Written by the pipeline owner session (branch `creature-pipeline`) before the design of record. It compares the current approach (the Creature Studio experiment, the Akinza construction loop, and the 2026-09 animation studies) against game-industry character pipeline practice and against Nick's stated goals. It changes nothing. The design of record that follows it is `creature-pipeline-design.md`.

Delivery target (Nick, 2026-10-14): a live 3D asset that runs well in mobile browsers is the primary deliverable; sprite sheets in `xalians-frame-atlas-v1` are a render output derived from it when a game stays 2D. Promotional 3D clips and 3D aspects in future games stay possible. Every gap below is judged against that target.

Vocabulary used here, defined once: a **mesh** is points, edges and faces; a **sculpt** is a dense mesh shaped for look only; **retopology** is rebuilding a clean low-polygon mesh over a sculpt so it deforms and renders well; **UVs** are the flat 2D map of a surface that textures paint onto; **baking** projects sculpt detail into texture images such as a normal map; a **skeleton** is the joint hierarchy that deforms the mesh; **skinning** is the per-vertex weights that bind mesh to joints; a **control rig** is the animator-facing handle layer that stays in the authoring tool; a **blend shape** is a stored vertex offset for shapes joints handle badly; **LOD** is a cheaper copy swapped in at distance; **texel density** is texture pixels per unit of surface; **glTF** is the open 3D file format browsers load; a **draw call** is one material on one mesh submitted to the GPU.

## 2. Gap audit against industry practice

Each gap: what industry does, what we do, whether it matters for the ratified target, and the verdict (adopt, adapt, skip). "Matters" is judged for one art director plus agents, not a department.

| # | Gap | Industry practice | Current state | Verdict |
|---|---|---|---|---|
| G1 | No technical spec at intake | A character brief fixes target platform, triangle, joint and texture budgets, units, axes, scale, texel density, skeleton class and root-motion policy before art starts | Intake records lore, silhouette, must-have features and a part list. No budget, no units (studio units are arbitrary), no skeleton class, no export target | **Adopt.** The spec is the contract the whole pipeline validates against. Cheap to write, expensive to skip: the current sculpt-density meshes are unusable as shipped assets and that was never visible because nothing declared a budget. |
| G2 | Deformation checked last, if at all | A proxy skeleton is bound to the blockout and bent into extreme poses before any surfacing, because topology faults found after rigging force rework in skinning, UVs and bakes | The studio's readiness stage (stage 9, not built) was the first rig contact. The rig library never used an armature. No creature in this repo has ever been skinned | **Adopt.** A proxy rig gate right after the blockout. This is the single highest-value missing stage for a 3D target. |
| G3 | No retopology, UV, bake or LOD stages, and the part-built mesh was treated as the asset | Sculpt, then retopology to a game mesh, then UVs, then bakes, then LODs | The remeshed field union is the only mesh. 700K-vertex heads, no UVs, no maps. Every game-facing property is missing | **Adopt**, with the sculpt kept as a source. Agents cannot place edge loops by eye any better than they sculpt, so the method is a base mesh per rig module or class, authored once with loops, UVs and weights, wrapped (shrinkwrapped) onto each creature's sculpt and checked by numeric deformation tests; Blender's built-in QuadriFlow is the fallback for parts no base mesh fits. Part identity is kept as a vertex attribute through the remesh so it can seed skin weights. LODs: skip for now; game cameras are fixed and close. |
| G4 | No roster layer | Studios define a few skeleton classes, share clip libraries and rig modules inside each, and order the build so shared work lands first | Each creature is a fresh pipeline run. The rig library's body-plan templates are the only cross-creature structure and they are 2D-render-oriented | **Adopt.** 33 species fall into nine body plans: biped 11, quadruped 8, multiped 6, floating 2, serpentine 2, avian, amorphous, piscine, swarm 1 each. Body plan is the wrong key to group rigs by: wings cross four plans (Avilily, Dromeus, Terragoyle, Vespersyn) and "multiped" mixes crabs, a centipede, a spider and a rooted body. The roster layer is therefore rig modules with parameters (spine, limb chain with leg count, wing, tail or tentacle chain, jaw) plus locomotion archetypes, assembled per species, not six fixed skeletons. A common move vocabulary (idle, hurt, faint, light, heavy, signature) mapped from the derived-acts tables onto a few animation archetypes is what makes 33 non-humanoids affordable. |
| G5 | No look-dev scene or style bible | One fixed neutral lighting scene and turntable; a short bible: palette and value rules, shape language, detail level, texel density, a material vocabulary per substance, outline rule, silhouette test | The studio has standard cameras and a clay material, which is half a look-dev scene. Render styles exist in the rig library. No bible; the look is still Nick's lean toward toon from 2026-09-21 and nothing ratified | **Adopt, small.** One scene file, one page of bible, ratified by Nick on the first creature, then applied. The lighting model decision (toon with outline versus PBR) is a question for Nick in the design. |
| G6 | Checks are measures, not validators | Importers run validators: naming, budgets, units, manifold, UV overlap, influence count, missing weights, bounds, bone and morph target caps, material count, texture size and compression, animation data size; plus a frame-time smoke test on a real device, because numbers alone prove nothing about frame rate; a failed validator blocks the handoff | The studio has two true gates (outputs hashed, one closed manifold) and everything else reports. Nick ruled rules must not be applied literally | **Adapt.** Split checks into three kinds: engine-breaking (blocks: non-manifold, unweighted vertices, more than four influences, wrong axes or scale, missing UVs, exporter errors), budget (reports, with the number beside the budget), and taste (never automated). This honors Nick's ruling and still catches the class of problem that breaks a game. |
| G7 | Agents not organized as departments with contracts | Modeling hands a mesh to rigging under a written spec; each department has input and output contracts and a reviewer | Roles are orchestrator, builder, critic, planner, toolsmith. Contracts exist for the build report, not for what each stage must deliver to the next | **Adapt.** Not departments (there is no team), but stage contracts: each stage has a named input artifact, output artifact, validator set and reviewer. The agent that builds a stage never reviews it. |
| G8 | Progress by critic score | Review is a named-defect list against a reference under identical conditions | The studio already tracks defects not scores (its best decision); the Akinza loop proved scores plateau at 6 to 7 with noise | **Keep.** Already right. |
| G9 | Sculpt method | A sculptor shapes form by eye; studios doing AI reconstruction treat it as a base to retopologize, never the asset | Hand-placed masses stalled four rounds; the reconstruction trial read better than the blobs on sight but was scored 5 of 10 by its own critic. The experiment adopted reconstruction as the sculpt layer two days ago | **Adopt the finding, change the tool policy.** Reconstruction is the right sculpt source for soft look-driven parts. See G12 for which model may ship. |
| G10 | Reuse by parts | Shared rig modules (spine, leg, tail, wing) and shader recipes; never shared meshes between characters | The reuse plan already says procedures not parts, and creature-owned numbers | **Keep**, and extend the same rule to rig modules and material recipes, which are exactly the things industry shares. |
| G11 | Review conditions | Identical lighting, camera, scale and background for every review; before and after side by side | Standard cameras and a sprite-size view exist; Nick asked for numbered checks with one big picture each | **Keep** and fold into the look-dev scene. |
| G12 | Tool licensing for shipped geometry | A studio clears every tool whose output ships | Hunyuan3D-2's license (section 5c) bars use, reproduction, modification, distribution or display of its Outputs outside the Territory, which excludes the EU, UK and South Korea; section 5b bars using Outputs to improve other AI models; the 1 million monthly active user test applies at the version's release date. xalians.com is public worldwide. A mesh retopologized from a reconstruction, and arguably a part fitted to one in 3D (the experiment's `fit3d.py`), is a result of the Works | **Decision for Nick.** Options: (a) use Hunyuan reconstructions as pictures to look at only, never as geometry that anything shipped is fitted to or derived from; (b) switch the sculpt source to an MIT-licensed model for anything that ships: TripoSG is MIT (verified at its repository and model card) but lists more than 8 GB of VRAM, over this laptop's 6.5 GB ceiling, so it must be tested with CPU offload before it is counted on; TRELLIS is MIT but needs about 24 GB; (c) accept the territorial risk. Recommendation: test (b) in the slice, fall back to (a). |
| G13 | Units and axes | Metric units, one up axis, documented export conversion | Studio units are arbitrary; the rig library has its own stage. Blender is Z-up, glTF is Y-up (the exporter converts, but only if the scene is at real scale) | **Adopt.** Meters, creature height from the species size band at the 50th percentile, origin on the floor under the body's center (floaters, serpents and the swarm record their rest height in the spec and keep the ground point as origin), facing -Y in Blender, which the exporter maps to glTF +Z, the format's front. |
| G14 | Animation as a UX budget | Turn-based games cap clip length, allow skipping, and put hit frames in animation events | The atlas contract has visual markers already (cue times). No per-game rule yet | **Adapt.** Markers become named animation events in the glTF clips; the length budget per clip is set in the design and is a lever. |
| G15 | Fur | Texture-only, shell, cards or strands, in rising cost; alpha sorting and overdraw are the mobile killers | Fur is deferred to a surface stage; Akinza's surface work used Blender hair. Nothing mobile-safe exists | **Adapt.** Mobile target means texture fur with a baked normal and a silhouette fringe where the sheet demands it; strand fur stays a render-only option for promotional clips and sprite renders. |
| G17 | No runtime delivery budget (missed in draft 1) | Budgets per scene, not per creature: download size, texture memory, draw calls, bone count, morph target count, animation data size; textures KTX2 or Basis compressed; meshes quantized and compressed (meshopt or Draco); keyframes sampled sparsely with optimization | Nothing. Blender's exporter bakes every bone every frame by default; the rig library stores a shape key per frame, which would explode as morph targets; Duel puts up to 12 creatures on screen and Reclamation rosters are twelve; the site has no 3D runtime chosen | **Adopt.** A per-scene budget for twelve creatures sets the per-creature budget; the first creature measures real frame time on a phone; the runtime (three.js or model-viewer) is chosen in the slice with its bundle cost counted. |
| G18 | The toon look does not survive export (missed in draft 1) | A runtime look is a shader in the engine; outlines on mobile are an inverted hull (doubles vertices and draw calls) or a post pass (needs depth and normals, costs fill rate) | The rig library's toon style is Blender's Toon BSDF plus Freestyle, both render-time only; neither reaches glTF | **Adapt.** The lighting decision becomes a runtime prototype A/B in the browser viewer, costed per technique; sprite sheets are rendered from the same runtime so 2D and 3D match. |
| G19 | Animation by agents (missed in draft 1) | Animators keyframe by eye; for non-humanoids studios lean on procedural gaits and layered secondary motion | Agents keyframe by eye no better than they sculpt. The rig library already proved the alternative: performances as code (eased key tracks with lag, solved legs) baked to frames | **Adopt.** Clips are parametric per locomotion archetype (gait, undulation, spring tail, hover bob) generated as code and baked to glTF, reviewed as moving results; shared clips retarget only inside a class with the same joint names and rest pose. |
| G20 | Individual variation (missed in draft 1) | One asset per character with runtime parameters | The generator rolls a size percentile and a finish per individual; the asset has no parameters | **Adopt.** The asset spec declares runtime parameters: uniform scale from the size band, finish as material parameters, and which properties may vary without breaking animation. |
| G21 | The swarm (missed in draft 1) | Crowds use instanced rigid parts with procedural motion or vertex animation textures | Vespersyn as one skinned mesh per member would not instance in three.js (reviewer's general knowledge, to verify) | **Adapt.** Vespersyn gets its own route when its turn comes: a lead figure plus instanced minors. |
| G16 | Asset tracking and ceremony | Large-team tooling, handoff meetings, motion capture | n/a | **Skip.** One director and agents; the studio's git-tracked records are the right size. Motion capture does not apply to non-humanoids built here. |

## 3. Gaps against Nick's goals, beyond industry practice

- **He must only judge taste.** Every stall in the record came from presenting work with a nameable flaw, or from a hold he never set. The studio's sourced holds and the "do not hand off known flaws" rule are right; the missing piece is a pre-presentation checklist per stage that an independent reviewer runs cold (stage contract, G7).
- **Cost per approved stage is unknown.** The studio collects Codex image tokens per build and can collect subagent tokens by tag, but no stage has a summed cost on record. The design makes the stage close write the number.
- **Nothing has reached the half of the pipeline that creates most of the cost for non-humanoids.** Rigging and animation are where the roster's nine body plans bite. The experiment has spent all its effort on the first third. The design front-loads a rig-ability check and builds the roster layer before the second creature.
- **Waste pattern to prevent.** Both Akinza runs lost most of their tokens to tools built on speculation mid-loop. The design rule: no new tool mid-stage; a tool is proposed at a stage close with a 20-minute smoke test, or not at all.

## 4. What to keep from the experiment, on merit

Keep: record kinds and evidence-hash approvals; defects over scores; sourced holds with "Blocked by"; the blob store and S3 keep set (already paid for, tested); the standard cameras and sprite-size check; the vision board and model sheet stages (they closed in a day each and gave Nick decisions he could make); the experiment log habit.

Rebuild: the geometry path (field-union sculpts become a sculpt source, not the asset); the stage list (add technical spec, proxy rig, retopology, UVs and bake, rig, animate, export and validate); the review screen only if a page per stage proves cheaper than Artifact pages (open; the Artifact path needs no site code).

Discard: the Akinza loop's scoring loop, toolsmith stage, and planner ranking; the per-part budget refusals as a question for Nick (he opened budgets on 2026-10-13); the "Phase 1 ends at a surfaced model" boundary, because for a 3D target the surfaced sculpt is a midpoint.

## 6. The cold challenge (2026-10-14)

An independent Opus reviewer read draft 1 cold and returned twelve findings. Accepted and folded in above: the biped count (11), the forward axis (-Y), the overstated reconstruction result, the missing runtime budget (G17), the toon-export problem (G18), retopology by base mesh and wrap rather than by-eye loops (G3), rig modules instead of fixed classes (G4), parametric animation (G19), individual variation (G20), the swarm route (G21), skipping LODs, the fuller validator list (G6), and the license corrections (G12). Rejected: none. Three of its points came from general knowledge rather than the repo (TRELLIS and TripoSG memory needs, three.js skinned instancing, the glTF axis mapping); the TripoSG license and memory figure were then verified online, and the axis mapping against Blender's exporter convention.
