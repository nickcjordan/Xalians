# Audit Brief 2: Xalians Creature System — Post-Revision Audit

You are re-auditing a game-data design you (or a prior auditor) reviewed once before. Read `CODEX-AUDIT-BRIEF.md` in this directory first for the full system description, then apply the corrections and additions below, which supersede it. Your job is the same: find holes — logical gaps, contract ambiguities, failure modes, internally inconsistent rules. Deliver findings, not restatement. Pay special attention to (a) whether the NEW pieces below introduce fresh problems, (b) whether they interact badly with anything retained from the original design, and (c) regressions: places where a fix reintroduced an old problem in a new form.

## Corrections to the original brief (rulings made after it was written)

1. **Anomaly concept scrapped entirely.** No off-graph secondaries, no `anomalous` field anywhere. Element odds are now 75% no secondary / 25% one on-graph secondary. The element block is `{primary, affinities}` only.
2. **All ability intensity values are 0-100** (the 1-10 scale in the old brief is dead). Uniform 0-100 for every graded value stands.
3. **A reserved "mystery trait" pool was also scrapped.** The trait vocabulary at launch is exactly 24 keys, nothing reserved.

## New ratified pieces since the first audit

4. **Anatomy field.** `physiology.anatomy` is a list of registry-keyed functional parts (e.g. `["pincers", "walking-legs"]`). Validation rule: every PHYSICAL instrument a species declares for abilities must appear in its anatomy; non-physical instruments (e.g. `mind`) validate against senses/traits instead. A comprehensive parts vocabulary is being built in a dedicated deep dive. Open sub-question: one vocabulary shared with instruments, or two linked ones.
5. **Lifespan.** Xalians do not age; their bioengineered bodies wear out (canon). `physiology.lifespan` is a species-set enum, never rolled per individual, never expressed in years: `fleeting | short | standard | long | enduring | ageless`. `ageless` = does not wear out but can still be killed; species-declared (e.g. non-corporeal species). Species values are authored via a wear rubric: mass + metabolic intensity, composition, home-world harshness.
6. **Genome chirality marker.** `physiology.genome: { "chirality": "levo" | "dextro" | "achiral" }`. A vestigial, deliberately gender-free dimorphism marker: rolled 50/50 levo/dextro; `achiral` is species-declared only, never randomly rolled. The platform never displays or maps it to gender; no ordering or rank implied. Must ship in generatorVersion 1.0.0.
7. **Communication split.** The vague `signaling` value is dead. `communication` is an array from `vocal | vibration | display | chemical | telepathic`. Empty array = explicitly cannot communicate.
8. **Environmental block** (replaces `respiration` enum and `climateTolerance`). Two fields: `breathes` (array; phases where respiratory exchange works; `[]` = does not breathe) and `environmentalTolerance: { ambientMedia: [...], temperatureC: { min, max } }` (what can safely surround the body; endpoints = "sustained normal activity" per registry). KEY DESIGN DECISION: **media are phases, chemistry is elements.** The media enum is closed: `gas | liquid | vacuum` (exhaustive by physics). What a particular liquid IS made of is an elemental question answered by the existing 14x14 type-effectiveness matrix (a chemical swamp = liquid + Chemical-type environmental exposure; its native breathers are Chemical-element and unharmed; a water-native breather in it can breathe phase-wise but takes typed exposure). Games derive drowning from "submerged in an ambientMedia entry not present in breathes". Solid is not a medium (living in rock/sand = the burrow capability). Explicitly deferred until a species demands them: pressure, humidity, atmospheric composition, per-medium temperature ranges. Breathing mechanism (organs) is never record data.
9. **Explicit-none principle** (refines the omit-when-N/A contract). Universal dimensions — questions every creature has an answer to (communication, diet, breathes, lifespan, covering) — are ALWAYS present, with "nothing" stated explicitly: empty array (`communication: []`, `breathes: []`, `favors: []` for the balanced archetype) or explicit value (`diet: "none"`, `covering: "bare"`, `lifespan: "ageless"`, graded values at 0). Additive extras (composition.secondary, senses.special, rolled traits, reserved appearance fields, non-signature descriptions, absent affinities) are omitted when absent.
10. **Trait renames** (role-nouns became descriptors; roles belong to the archetype roster): healer→healing, guardian→protective, pack-hunter→pack-bonded, lone-stalker→solitary, charger→ramming.
11. **Trait tilt system.** Trait draws are weighted rolls tilted by the individual's earlier rolls (generation order: physiology → archetype → attributes → affinities → traits → temperament → finish → abilities). Tilts live in trait registry entries; never gates; never below species-authored floors; magnitudes tuned via simulated batches. Tiers: PHYSIOLOGY tilts (stealthy ↓mass; anchored ↑mass; menacing ↑size; ramming ↑sprint; perceptive ↑graded-senses average; telekinetic ↑manipulation; armored ↑mass where rolled), ATTRIBUTE tilts (resistant ↑resilience; mind-sealed ↑willpower; foresighted ↑instinct; hypnotic ↑charisma; inspiring ↑charisma; slippery ↑agility; regenerative ↑vitality; pack-bonded ↑charisma; solitary ↓charisma), AFFINITY tilt (phasing ↑ghost affinity, rolled-on-corporeal path only). Accepted cost: bounded rich-get-richer compounding, embraced as coherence. Untilted traits: healing, protective (their only honest correlate, temperament, rolls later), toxic, volatile, reflective, luminous (species-fixed drivers), nocturnal (habit, not body).
12. **Manipulation stays single and outcome-based** (how well it handles objects); the means (physical vs telekinetic) is derived from anatomy + the telekinetic trait.
13. **Specimen-vs-template contract sentence:** every value in a record describes this individual; the species-level view lives in the version-pinned species registry template.

## What to audit

Deliver a numbered list of findings, each with severity (high/medium/low), the specific hole, and a concrete suggestion. Be adversarial; agreement is not useful. Write your full findings to `CODEX-AUDIT-FINDINGS-2.md` in this directory.
