# Creature records tooling

Part 5 of the creature pipeline (design: `docs/design/creature-records-and-tooling.md`). Python 3 standard library only. Records are JSON files under `art/roster/<key>/`, written only through `roster.py` (atomic writes, LF endings). Git is the history; binaries live in a blob store outside the repo.

## Usage

Run from the worktree root.

```
python art/pipeline/records/roster.py init luceras
python art/pipeline/records/roster.py stage open luceras 01-intake        (also: intake, 1)
python art/pipeline/records/roster.py build plan luceras sculpt --goal "..." --scope "head" [--defect D-xxxx] [--kind build] [--input path ...]
python art/pipeline/records/roster.py build report luceras B-xxxx --file report.json
python art/pipeline/records/roster.py defect add luceras sculpt --description "..." [--camera ... --region ... --origin ...]
python art/pipeline/records/roster.py defect close luceras D-xxxx
python art/pipeline/records/roster.py hold add luceras sculpt --statement "..." --source nick --words "..." --date 2026-10-13 [--strength firm|soft]
python art/pipeline/records/roster.py hold add luceras sculpt --statement "..." --source inferred --reason "..."
python art/pipeline/records/roster.py hold lift luceras H-xxxx
python art/pipeline/records/roster.py decision add luceras sculpt --who nick --kind approval --words "..." --build B-xxxx --evidence <hash> [--evidence <hash>]
python art/pipeline/records/roster.py decision add luceras sculpt --who orchestrator --kind audit --words "..." --defect D-xxxx
python art/pipeline/records/roster.py decision add luceras sculpt --who nick --kind budget --words "..." --amount 12
python art/pipeline/records/roster.py review add luceras B-xxxx --file review.json
python art/pipeline/records/roster.py stage close luceras sculpt --approval N-xxxx
python art/pipeline/records/roster.py picks file luceras vision --from picks.json
python art/pipeline/records/roster.py status luceras
python art/pipeline/records/roster.py next luceras
python art/pipeline/records/roster.py blob put <file>
python art/pipeline/records/roster.py blob get <hash> [out]
python art/pipeline/records/roster.py cost collect luceras B-xxxx
python art/pipeline/records/roster.py page luceras
```

`blobs.py`, `cost.py` and `page.py` also run on their own. Any record can be named by full id, `B-k3f9`, or the bare alias `k3f9`. Exit code is 0 on success and 1 on a refusal (message on stderr).

### Files

A build report (`--file`) is JSON with `outputs` (list of `{name, hash}`, required), `blockedBy` (required; write `nothing` if so), optional `defectResult`, `newDefects`, `validators`, `checks`, `blenderSeconds`, `codexTokens`. A key named score, rating or grade is refused. Each entry in `checks` is `{title, question, before, after, reference, sprite, recommended}`, where the image fields are blob hashes; the review page numbers them and inlines the images.

A review file is `{"verdict": "pass"}` or `{"verdict": "defects", "defects": ["name", ...], "notes": "..."}`.

### Filing picks

`picks file` takes an export of the selection screen's store: `picks` (element to `{alias, label, blob, at}`), `requests` (element to `{kind: new-set|mix, text, at}`), `status` (`{submitted, at}`) and an optional `composite`. Every pick must name a build in that stage whose reported outputs include the blob hash, or the whole file is refused (naming the element) and nothing is written. Each pick becomes a Nick decision of kind `pick` (field `element`, bound to the build and blob). Each request becomes a Nick decision of kind `request` (fields `element`, `requestKind`) and appends its id to the `attempts` list of the defect "<element>: no option accepted" (created if missing, reopened if closed), so the two-regeneration stall rule sees it. If `status.submitted` is true, one `approval` decision is written, bound to every picked build (`binds.builds`, with the first as `binds.build` so `stage close` accepts it) and every picked blob, and carrying the `composite` block; its id is printed for `stage close --approval`. Running the same file twice adds nothing (keys: element plus alias plus kind; requests by element, request kind and text; the approval by its set of picks).

### Refusals

- a build report without outputs, without `blockedBy`, or with a score
- a third build on a defect with no audit decision naming it
- a stage close without an approval decision bound to a build and evidence hashes
- a picks file naming a blob that is not in the picked build's outputs, or a build from another stage
- a build input pinned under another creature's folder
- a build, defect, hold or decision in a stage that is not open; a review of a build with no report; a hold sourced to Nick without words and date, or inferred without a reason

## Layout

```
art/roster/<key>/
  creature.json                 species facts and hashes, tech spec, budget, stage states
  review.html                   generated by `page`
  stages/<nn>-<name>/
    builds/B-<id>.json   defects/D-<id>.json   holds/H-<id>.json   decisions/N-<id>.json
    review.json                 reviewer verdicts (R- ids)
    cost.json                   written at stage close
```

Ids are `<kind>-<26 chars>`: ten Crockford base32 characters of the millisecond time, sixteen random, so they sort by creation. Every record also has a four-character lowercase `alias`, unique within the creature. Kinds: C creature, B build, D defect, H hold, N decision, R review entry.

Stage states: `not-started`, `open`, `closed`, `stale`. Closing a stage marks later closed stages stale. Stages: 01-intake, 02-vision, 03-sheet, 04-blockout, 05-sculpt, 06-gamemesh, 07-surface, 08-rig, 09-animate, 10-export, 11-retro.

## Blob store

`C:\dev\art-data\pipeline\blobs\<aa>\<sha256>` with `manifest.json` (hash to original names, size). Override the root with `XALIANS_BLOBS`.

## Cost

Tag each builder agent's description or first message with `[build B-xxxx]` (the alias the plan prints). `cost collect` scans every `*.jsonl` under `~/.claude/projects` (override: `XALIANS_PROJECTS`), matches the tag in the first user message or the sibling `.meta.json` description, and sums usage per role (the meta `agentType`) deduplicated by `message.id`. The result goes in the build's `cost` block; `uncovered: true` means no transcript carried the tag. Blender seconds and Codex tokens come from the report. The orchestrator's own share is not collected here.

## Tests

```
python -m unittest discover -s art/pipeline/records/tests -v
```

Tests use temp directories through `XALIANS_REPO`, `XALIANS_ROSTER`, `XALIANS_BLOBS` and `XALIANS_PROJECTS`; they never touch the real roster or blob store.
